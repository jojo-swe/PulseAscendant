# Two acts and hardware ray tracing

Goal: retain every Act I chapter inside 300 seconds, then play the complete user-supplied Adventurous Uplift as Act II with new themes and real GPU ray tracing on supported Windows/Linux systems.

Architecture: one sample-exact combined stereo transport; separate per-act cues and FFT data. OpenGL continues to present the window, particles, bloom and captions. An optional dynamically loaded Vulkan compute backend traces triangle BLAS/TLAS with KHR ray queries, uploads its HDR result to the compositor and owns its resources independently. Unsupported devices select an explicitly identified OpenGL fallback. The normal executable must start without a Vulkan loader installed.

Constraints: preserve original music, v0.2 release and original Future Crew source. No simulated hardware RT labels. Probe capabilities per device. No new music generation or copyrighted asset dependencies. User has requested autonomous execution and public GitHub delivery.

Implementation sequence:

1. Prepare the full second WAV and a combined WAV whose Act II first sample follows Act I frame 14,399,999. Generate independent 24-band analysis. Test exact lengths, original prefix and second-track identity.
2. Extend timeline and `--show-info` with two acts, all 31 original chapters and a second cue sheet; add explicit act navigation and bounded export ranges. Test the join, seeking, loop and all camera variants.
3. Implement Vulkan instance/device selection, dynamic entry points, memory/resource lifetime, static BLAS, dynamic TLAS, descriptor/compute pipeline and host transfer. Trace moving geometry, reflection and shadow rays. Fail to a visible fallback on unsupported hardware; fail strict RT diagnostics if RT is requested but unavailable.
4. Implement four visually distinct scene layouts and music-reactive materials/cameras. Add a matching OpenGL fallback and integrate into the HDR compositor. Compile SPIR-V from pinned Vulkan headers/toolchain; ship the compiled shader so no runtime compiler is required.
5. Test missing loader/device behavior, resize and RT resource rebuild, motion, Act I/II transition, audio length checks, export boundaries, and native Windows/Linux builds. Run Vulkan validation where available. Independent final review and fix material findings.
6. Package separate Windows/Linux/source artifacts and deterministic 4K video; verify metadata and public release asset digests. Preserve previous publications.

Review focus: unsupported Vulkan / integrated GPU selection; non-coherent or device-lost memory; resize and first TLAS build synchronization; frame-exact join and end looping; exporter accidentally reading the old runtime music.

Acceptance: the runtime plays all 300 seconds of Act I and all decoded frames of Act II at normal speed, all worlds render and animate, hardware RT is evidenced by live Vulkan KHR AS builds and ray queries, and fallback is clearly distinguishable. 4K60 denotes exported resolution/frame rate, not a claim of interactive 4K60 performance. Native physical Linux RT and subjective quality remain separate acceptance grades.
